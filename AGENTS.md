Holon is small and should stay small. We want the fewest concepts that explain everything, each expressed exactly once. We abstract when a concept is real, not in case it might become one, and a little repeated code is better than an early abstraction. When something is wrong, we fix the cause; we never hide an invalid state behind a fallback or patch a symptom where it shows. The data model and the boundaries come first, the logic follows from them. Nothing is deployed, so there is no legacy to keep: rework toward the best end state.

Code is explicit and boring: plain flow, visible errors, no hidden state or IO, the standard library before a dependency, measurement before optimization. Before accepting a change, ask whether it could have fewer parts, whether any abstraction is only there just in case, whether anything in it is not needed, and whether a newcomer could explain each part in two sentences. Prefer deleting, simplifying and merging over adding.
